## Why

`agentctl install <harness>` writes integration files (a pi extension, Claude
hook entries) onto the user's machine, but there is no way to cleanly remove
them. Users who want to stop using agentctl, switch harnesses, or debug a stuck
integration currently have to manually edit `~/.pi/agent/extensions/agentctl.ts`
or hand-edit `~/.claude/settings.json`. `agentctl uninstall <harness>` should
mirror `agentctl install` exactly so removal is as easy and safe as
installation.

## What Changes

- Add a new `agentctl uninstall <harness>` subcommand with the same `HARNESS`
  value enum as `agentctl install` (`pi`, `claude`).
- `agentctl uninstall pi`: deletes `~/.pi/agent/extensions/agentctl.ts` if it
  exists and was generated by agentctl (or is simply present under that managed
  path); no-op if already absent.
- `agentctl uninstall claude`: removes only the agentctl-managed hook entries
  (current `agentctl state set ...` / `agentctl state clear` commands, and
  recognized pre-rename `agentctl set-state ...` / `agentctl clear-state`
  commands) from `~/.claude/settings.json`, leaving any user-defined hooks
  untouched; removes now-empty event arrays/objects it created but never touches
  non-agentctl-authored structure; no-op if no agentctl entries are present.
- Both subcommands print a human-readable summary of what was removed (or that
  nothing needed removing), following the existing `+`/`~`/`=`/`-` summary
  conventions used by `install`.
- Enforce (structurally, not just by convention) that `uninstall` supports the
  exact same harness list as `install`: both commands share the single `Harness`
  enum, so adding a new harness variant automatically requires (and exposes) it
  in both `install` and `uninstall`.

## Capabilities

### New Capabilities

- `uninstall-command`: The `agentctl uninstall <harness>` subcommand, its shared
  `Harness` enum contract with `install`, and its harness-dispatch behavior.

### Modified Capabilities

- `pi-state-hooks`: Adds the requirement that `agentctl uninstall pi` removes
  the generated `~/.pi/agent/extensions/agentctl.ts` extension file.
- `claude-state-hooks`: Adds the requirement that `agentctl uninstall claude`
  removes only the agentctl-managed hook entries from `~/.claude/settings.json`,
  preserving all other user configuration.

## Impact

- `src/main.rs`: new `Commands::Uninstall { harness: Harness }` variant
  dispatching to a new handler; `Harness` enum is reused as-is.
- `src/commands/hooks.rs` (or a new `src/commands/uninstall.rs`): new
  `run_uninstall`, `uninstall_pi_to`, `uninstall_claude_to` functions mirroring
  the existing `run_install`, `install_pi_to`, `install_claude_to` structure,
  plus new unit tests.
- No changes to the state file format,
  `agentctl state set`/`agentctl state clear` behavior, or existing `install`
  behavior.
