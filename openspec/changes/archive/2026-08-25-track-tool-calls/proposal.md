## Why

`agentctl list` today shows only a coarse `working`/`idle`/`blocked`/`done`
status per agent pane, with no visibility into how much concurrent tool activity
is happening inside a `working` agent. When several tool calls are in flight
(e.g. an agent fanning out multiple bash/read/edit calls), the operator has no
signal that anything unusual is going on versus a single quiet tool call. The
`agent-state` spec already anticipates this: `state.json` explicitly calls out
"a count of active tool calls" as future per-pane state. This change adds that
counter and surfaces it in `agentctl list` output.

## What Changes

- Add a new `active_tools` field (`u32`, default `0`) to `state.json` /
  `AgentInfo`, tracking the number of tool calls currently in flight for a pane.
- `agentctl agent event TOOL_CALL_START` increments `active_tools`;
  `agentctl agent event TOOL_CALL_RESULT` decrements it (floored at `0`),
  independent of the existing `--type elicitation` status-FSM transition.
- Extend the pi extension (`~/.pi/agent/extensions/agentctl.ts`, generated by
  `agentctl install pi`) to subscribe to pi's `tool_call` and `tool_result`
  events — which it does **not currently do at all** — and call
  `agentctl agent event TOOL_CALL_START --id <toolCallId> --harness pi` /
  `agentctl agent event TOOL_CALL_RESULT --id <toolCallId> --harness pi`
  respectively, so the counter is driven in real time. Without this,
  `TOOL_CALL_START` / `TOOL_CALL_RESULT` are never dispatched by pi sessions
  today.
- `agentctl list` output gains a fifth column for the active tool count,
  separated from the `state` column by the same two-space delimiter used between
  every other column: `N tool` for exactly one, `N tools` for `N > 1`, and an
  empty column (no dangling delimiter) when `active_tools == 0`. Example:
  `pi  agentctl  0.0  working  1 tool`, `pi  agentctl  0.0  working  3 tools`,
  `pi  agentctl  0.0  working` (no active tools).
- `session_start` / `SESSION_STARTED` and session cleanup continue to reset
  per-pane state as a whole, which resets `active_tools` back to `0`.

## Capabilities

### New Capabilities

(none — this extends existing capabilities rather than introducing a new one)

### Modified Capabilities

- `agent-state`: `state.json` schema gains an `active_tools` field; add
  requirements for its default value, increment/decrement behavior, and reset on
  `SESSION_STARTED`.
- `agent-events`: `TOOL_CALL_START` / `TOOL_CALL_RESULT` gain a side effect of
  mutating `active_tools` in addition to the existing status-FSM transition.
- `pi-state-hooks`: the generated pi extension gains **new** `tool_call` /
  `tool_result` handlers (pi currently has none) that call the two events above.
- `list-sessions`: `agentctl list` gains a fifth column, using the existing
  two-space column delimiter, showing the active tool count when non-zero.

## Impact

- `src/state.rs`: `AgentInfo` struct, read/write helpers.
- `src/commands/agent_event.rs`: increment/decrement logic for `TOOL_CALL_START`
  / `TOOL_CALL_RESULT`.
- `src/commands/hooks.rs`: embedded `PI_EXTENSION_CONTENT` template.
- `src/commands/list.rs`: `format_panes` state-column rendering.
- Existing `state.json` files written by older `agentctl` binaries lack
  `active_tools`; it must deserialize with a default of `0` for backward
  compatibility.
