## Why

`rd list` today shows only a coarse `working`/`idle`/`blocked`/`done` status per
agent pane, with no visibility into how much concurrent tool activity is
happening inside a `working` agent. When several tool calls are in flight (e.g.
an agent fanning out multiple bash/read/edit calls), the operator has no signal
that anything unusual is going on versus a single quiet tool call. The
`agent-state` spec already anticipates this: `state.json` explicitly calls out
"a count of active tool calls" as future per-pane state. This change adds that
counter and surfaces it in `rd list` output.

## What Changes

- Add a new `active_tools` field (`u32`, default `0`) to `state.json` /
  `AgentInfo`, tracking the number of tool calls currently in flight for a pane.
- `rd agent event TOOL_CALL_START` increments `active_tools`;
  `rd agent event TOOL_CALL_RESULT` decrements it (floored at `0`), independent
  of the existing `--type elicitation` status-FSM transition.
- Extend the pi extension (`~/.pi/agent/extensions/radr.ts`, generated by
  `rd install pi`) to subscribe to pi's `tool_call` and `tool_result` events and
  call `rd agent event TOOL_CALL_START --id <toolCallId> --harness pi` /
  `rd agent event TOOL_CALL_RESULT --id <toolCallId> --harness pi` respectively,
  so the counter is driven in real time.
- `rd list` output's state column now appends the active tool count when greater
  than zero: ` 1 tool` for exactly one, ` N tools` for `N > 1`, and no suffix at
  all when `active_tools == 0`. Example: `working 1 tool`, `working 3 tools`,
  `working` (no active tools).
- `session_start` / `SESSION_STARTED` and session cleanup continue to reset
  per-pane state as a whole, which resets `active_tools` back to `0`.

## Capabilities

### New Capabilities

(none — this extends existing capabilities rather than introducing a new one)

### Modified Capabilities

- `agent-state`: `state.json` schema gains an `active_tools` field; add
  requirements for its default value, increment/decrement behavior, and reset on
  `SESSION_STARTED`.
- `agent-events`: `TOOL_CALL_START` / `TOOL_CALL_RESULT` gain a side effect of
  mutating `active_tools` in addition to the existing status-FSM transition.
- `pi-state-hooks`: the generated pi extension gains `tool_call` / `tool_result`
  handlers that call the two events above.
- `list-sessions`: the state column's rendering rule is extended to append the
  active tool count when non-zero.

## Impact

- `src/state.rs`: `AgentInfo` struct, read/write helpers.
- `src/commands/agent_event.rs`: increment/decrement logic for `TOOL_CALL_START`
  / `TOOL_CALL_RESULT`.
- `src/commands/hooks.rs`: embedded `PI_EXTENSION_CONTENT` template.
- `src/commands/list.rs`: `format_panes` state-column rendering.
- Existing `state.json` files written by older `rd` binaries lack
  `active_tools`; it must deserialize with a default of `0` for backward
  compatibility.
